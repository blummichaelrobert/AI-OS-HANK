## Why this document exists

The AI OS ships under **AGPL-3.0**. That choice is deliberate and it is also *reversible* — but only while a single party holds copyright over the whole work.

The moment an outside contribution merges without an agreement in place, that contributor owns their lines. Relicensing then requires locating and obtaining consent from every past contributor. In practice that is permanent.

**This CLA preserves the option to loosen the license later.** It does not take ownership of your work away from you.

## Scope — what counts as a contribution

Any work intentionally submitted to this project for inclusion. This includes:

- Prose architecture files (`.md`) — core files, Captain Function Contracts, Colonel Mission Briefs, Battle Plans, templates
- Code (`.py`, `.js`, `.tsx`, `.html`)
- Documentation, examples, and configuration

It does not include a comment on an issue, a bug report, or a discussion post.

## What the maintainer commits to in return

1. **This project stays open source.** The relicensing right exists to allow a move to a *more permissive* open license (for example Apache-2.0) if adoption requires it. It is not a path to a proprietary fork of community work.

2. **Any relicensing is announced publicly** in the repository before it takes effect.

3. **Attribution is preserved.** Contributors are credited in the project's contributor record regardless of license changes.

---

## Alternative worth considering

A lighter-weight option is the **Developer Certificate of Origin (DCO)** — a one-line `Signed-off-by:` in each commit. It is far less friction for contributors.

**The tradeoff:** DCO certifies that you had the right to submit the code. It does **not** grant relicensing rights. If preserving the AGPL-to-permissive escape hatch is the goal, DCO alone does not achieve it.

Use DCO if you are confident AGPL is permanent. Use this CLA if you want the option open.
